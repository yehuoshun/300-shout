# 真机首验陪跑清单（第一次打开 300英雄 时照着做）

> 目标：第一次上真机就把「窗口标题 → 标定 → 检测 → 守卫 → 发送 → 全链路」逐一验证掉，
> 任何一步不过就停在那一步查，**不要跳步**。全程命令都在仓库根目录执行。
>
> 原则：**宁可漏喊，不可误发**。没验过发送链路，就不要看它「会不会自动喊」。

准备：游戏进**自定义/训练模式**（别开真对局）；桌面留一个记事本窗口用来对比；
显示器如果不止一块，先确认游戏在哪块屏（`capture.output_idx`，主屏为 0）。

> 解释器：这台机器上系统的 `python` 是 Microsoft Store 的桩（跑起来直接 9009），
> 下文所有命令统一用仓库内的 `.venv\Scripts\python.exe`——里面已经装好 cv2 / dxcam / pydirectinput。
>
> **用面板（v3.2，推荐）**：双击 `300-Shout.exe` 开控制面板（想换外观点右上角「外观」下拉框，四套随便挑，选完会记住）→ 点「标定 R 槽」框选大招图标 →
> 点「标定体检」看结论 → 切到游戏点「开始监控」→ 开大验证。下面 8 步的**判据完全适用**，
> 只是把命令换成了按钮；需要看详细日志时仍按下面的步骤在终端里跑一遍更稳。
>
> **用 exe 版（Releases 里的 `300-Shout.exe`）就免装 Python**：把下文的
> `.venv\Scripts\python.exe main.py` 换成 `300-Shout.exe`，标定那一步换成
> `300-Shout.exe --calibrate`、`300-Shout.exe --calibrate-check`。判据与期望日志完全一样。

## ☐ 0. 离线自检（不碰屏幕、不发键，30 秒）

```bash
.venv\Scripts\python.exe main.py --version      # 期望：300-shout 3.0.0
.venv\Scripts\python.exe main.py --self-test    # 期望：末行 SELF-TEST OK: 触发 1 次, 台词=[...]
```

不过就先别往下走：说明 Python 环境/cv2 装错了（`pip install -r requirements.txt`）。

## ☐ 1. 查游戏窗口标题

```bash
.venv\Scripts\python.exe main.py --list-windows
```

从输出里找游戏那一行，把**稳定片段**填进 `config.json`：

```json
"chat": { "foreground_titles": ["300英雄"] }
```

判据：切到游戏窗口后再跑一次（这个命令**不抓屏、不发键**，只读前台标题）：

```bash
.venv\Scripts\python.exe main.py --check-guard
```

期望输出 `当前前台窗口: '...'` + `结果: 通过`。出现「不通过」就把实际标题片段填进去。
标题会在「窗口化/全屏」之间变化的话，留最短的公共片段（子串匹配、大小写不敏感）。

> 若游戏是**无标题的独占全屏**窗口（拿到的标题是 `None`），守卫会一直拦下。这种情况先记下来，
> 后面第 5 步再决定是否临时 `--no-guard`，**不要在这一步就关守卫**。

## ☐ 2. 标定 R 槽

```bash
.venv\Scripts\python.exe calibrate.py
```

1. 截图弹出后框选**技能栏 R 槽**（只框图标，别带边框/数字）。2K/4K 会自动缩到 1600×900 预览，
   坐标会换算回原分辨率，看到「预览已缩到 xx%」是正常的
2. 让大招处于【可用】，回车采集「可用态」
3. 放大招进 CD，选 `y` 再采一次「CD 态」（强烈建议采，有了它才能区分两态）
4. 写完自动体检

然后单独再跑一次体检：

```bash
.venv\Scripts\python.exe calibrate.py --check
```

判据：**没有「错误」行**，警告按提示处理。重点看三条：

| 体检项 | 不好的信号 | 怎么办 |
|--------|-----------|--------|
| 纹理 | 「纯色/无纹理」 | 框错了地方（框到黑边/空地），重新框图标本体 |
| 尺寸 | 「ROI 与基准图尺寸不一致」 | 标定后改过分辨率/UI 缩放，重新标定 |
| 两态可分 | 「两态分不开（差距 x.xx）」 | CD 态采错了（没进 CD 就采了），重采 CD |
| 建议阈值 | 给出的数记下来 | 第 3 步直接用它 |

## ☐ 3. 演练：只看检测，不发一个键

```bash
.venv\Scripts\python.exe main.py --dry-run --stats 10
```

切回游戏，**正常开大**（打训练假人/CD 好了就按 R），盯日志：

- 期望：`ready` 分数在可用时高、CD 时明显掉下来；触发时打印
  `[DRY-RUN] 检测到大招，本应发送：…`,**游戏里不会出现任何字**
- `ready` 恒 ≈1.0 不掉 → 框的区域没有 CD 变化，回第 2 步重框（常见：框到了固定图标底色）
- `ready` 在阈值附近抖 → 用 `--stats` 打印的 ready/cd 两个值，把 `detect.threshold`
  设到两者中间偏上（例如 ready 0.92 / cd 0.55 → 设 0.75）
- 触发太频繁（放一次大招触发好几次）→ `detect.confirm_frames` 加到 3、
  `detect.lock_seconds` 加到 4~5
- 一直不触发且体检警告「两态分不开」→ 回第 2 步

判据：**至少干净触发 1 次**，且同一次大招不重复触发。

## ☐ 4. 守卫：游戏不在前台，必须一个字都不发

演练还在跑的时候，`Alt-Tab` 切到记事本，再按一次 R（游戏在后台不会响应，可用游戏内
「大招 CD 好了以后切出去」的方式制造触发，或直接在游戏里放完大立刻切出去）。

判据：日志出现

```
检测到大招，但前台窗口 'xxx' 不在白名单 ['300英雄']，本次不发送（游戏需在前台）
```

且**没有**任何字被打进记事本。同时统计行还在涨（说明主循环没卡住）。

## ☐ 5. 单发测试：先确认「发得出去」，再谈自动

关掉演练进程（F9 或 Ctrl+C），切回游戏，跑：

```bash
.venv\Scripts\python.exe main.py --test-send "测试一下"
```

判据：游戏聊天框里出现「测试一下」并已发送。

发不出去时按这个顺序排（每改一项重跑一次）：

| 现象 | 改什么 |
|------|--------|
| 完全没打开聊天框 | `chat.open_key`（默认 `enter`；若游戏是 `t` 开聊天就改） |
| 发出半句 / 乱码 / 只有中文没了 | `chat.input_method` 改 `"clipboard"` |
| 字进了输入框但没发出去 | `chat.enter_delay` 加到 0.3~0.5 |
| 发到错误频道（队伍而不是公屏） | 见第 6 步 |
| 日志「前台窗口 … 不在白名单」 | 回第 1 步；确认是游戏在前台而不是启动器 |

## ☐ 6. 频道实测（一次就能定死）

在游戏里手动试一遍，把结果填进 `config.json`：

| 实测结果 | 配置写法 |
|---------|---------|
| 默认就在公屏，直发即可 | `"channel_keys": []`, `"text_prefix": ""` |
| 需要按 Tab 切频道 | `"channel_keys": ["tab"]` |
| 需要 Shift+Enter 切全部 | `"channel_keys": ["shift+enter"]` |
| 需要先打字 `/all 内容` | `"channel_keys": []`, `"text_prefix": "/all "` |

> 组合键写 `"shift+enter"`（内部 keyDown/keyUp 包夹）；`["shift", "enter"]` 是**两个独立按键**。

改完用第 5 步的 `--test-send` 再验一次，判据：字出现在**公屏**。

## ☐ 7. 全链路：真发一次

```bash
.venv\Scripts\python.exe main.py
```

- F8 暂停/继续（暂停时仍响应 F9），F9 立即退出
- 开大 → 日志 `发送成功` 类信息 + 游戏公屏出现台词
- 没有重复刷屏：`min_interval`/`max_interval` 已内置随机间隔

判据：3 次开大 = 3 条台词，间隔自然，且切出去时一条都不发。

## ☐ 8. 收尾与记录

- 日志在 `logs/300-shout.log`（2MB × 3 轮转），出问题把它带上

  先跑 `.venv\Scripts\python.exe calibrate.py --check`，必要时重新标定（记下是哪几个英雄）
